# Каркас-Проект: нормы и правила работы

Владелец — монтажник, не программист. Отвечать по-русски, простыми словами. Все расчёты в программе предварительные: на листах и в интерфейсе должна оставаться оговорка о проверке инженером. Не выдавать результат программы за готовый проект.

## 1. Устройство кода

- **Исходники — в `src/`, `index.html` собирается командой `node build.mjs` и вручную не правится.** Сборщик склеивает модули в один файл (GitHub Pages) и копию для claude.ai `dist/artifact.html`. Модули — обычные скрипты с общей областью видимости, порядок — по номеру в имени. Открывать только нужный модуль:
  - `01-util` общие функции · `02-spravochniki` справочники, роли деталей, `DEF`, localStorage · `03-geom-klimat-nagruzki` сетки, климат, нагрузки, балки
  - `04-build-model` `build(P)`: ростверк, пол, стены, крылья, проёмы, перекрытие, стропила, прогон · `05-pomeshcheniya-karkas-sten` помещения, ТЭП, укосины, каркас стены
  - `06-raschet` `calc`, ветер, подбор сечений · `07-specifikaciya-raskroy` спецификация, раскрой, смета · `07b-otdelka` отделка: каталог `FIN` (состав и цены), `finishCalc(M)` → `S.fin` (площади по помещениям, фасад, материалы), лист «Ведомость отделки» · `08-sovety` советы
  - `09-ui-forma-shablony` форма ввода, шаблоны `TEMPLATES`, история, вкладки · `10-3d` three.js · `10a-planner` планировщик АР: план рисуется мышью (стены, перегородки, проёмы, крылья, помещения), правит `P` и пересобирает модель; мебель, линейка, размеры комнат · `10b-mebel` каталог мебели и оборудования `FURN`, `P.furn`, условные изображения `furnPrims` (план, АР-1) · `10c-3d-dom` 3D-вид «Дом (АР)»: стены с проёмами, фронтоны и кровля из `facadeFaces()`, полы, мебель
  - `11-svg-osnova` примитивы SVG, размеры, рамка, штамп · `12-listy-plan-fundament-steny` Ф-1, Ф-2, АР-1, КД, мансарда · `13-list-fasady` фасады · `14-listy-krovlya-od` план кровли, КР-1, ОД · `15-listy-eksport-dxf` `makeSheets`, DXF, ZIP · `16-ui-tablicy-raschet` вкладки спецификации, расчёта, базы · `17-baza-znaniy` база знаний · `18-start` запуск
- Библиотеки: three.js 0.170 (3D) — ES-модуль с cdn.jsdelivr.net, подключается в `src/head.html` и кладётся в `window.THREE` (событие `three-ready`); свет в физических единицах (×π); с cdnjs — JSZip 3.10.1 и SheetJS 0.18.5 (подгружаются при экспорте).
- Единицы: геометрия — **мм**, нагрузки — **кПа (кН/м²)**, погонные — кН/м (= Н/мм), силы — кН.
- Поток данных: `P` (исходные данные, localStorage `karkas-proekt-v1`) → `build(P)` → модель `M` (стены, проёмы, детали `M.mem`, сваи, помещения `M.rooms`) → `calc(M)` (проверки `C.checks`, ветер `C.H`) → `spec(M,C)` (марки, раскрой, смета) → `advice()` → `makeSheets()` (SVG A3 → DXF).
- План прямоугольный A×B. Наружные стены: W1 (y=0, фасад), W2 (x=A), W3 (y=B), W4 (x=0). Перегородки `P.walls` (`axis` x|y, `c`, `from`, `to`, `bearing`) получают id I1, I2… Фронтоны G2/G4, стенки мансарды K1/K3.
- Помещения: `detectRooms(M,P)` режет внутренний контур гранями перегородок (допуск примыкания 40 мм) и объединяет свободные ячейки. Названия и назначение — `P.rooms` (привязаны к точке внутри помещения). Показатели — `tep(M)`.
- Новые поля в `P` добавлять в `DEF` и в `normalize()` (старые проекты из localStorage и JSON должны открываться). При несовместимом изменении формата — сменить ключ localStorage.
- АР и КР работают с **одной** моделью: правка в АР обязана пересчитывать КР. Не заводить вторую копию геометрии.

## 2. Оформление листов (СПДС)

Нормативная база: ГОСТ Р 21.101-2020 (основные требования к документации), ГОСТ 21.501-2018 (рабочая документация архитектурных и конструктивных решений), ГОСТ 21.201-2011 (условные изображения элементов зданий). Конкретные размеры знаков сверять с текстом стандарта; ниже — принятые в проекте правила.

- Лист A3 альбомный 420×297, рамка: поле 20 мм слева, 5 мм с остальных сторон; штамп 185×55 в правом нижнем углу (функции `frame()`, `wrapSheet()`).
- Шифры листов: `ОД` — общие данные; `АР-n` — архитектурные решения; `Ф-n` — фундамент; `КД-n` — развёртки каркаса стен; `КР-n` — конструктивные решения. Порядок в комплекте: ОД, АР, Ф, КД, КР. Ведомость листов — на листе ОД.
- Размеры — в мм без единиц, отметки — в метрах с тремя знаками: `±0,000`, `+2,800`, `−0,700` (функция `elvTxt`). За ±0,000 принят верх чернового пола.
- Координационные оси: цифрами — слева направо, буквами — снизу вверх. Буквы Ё, З, Й, О, Х, Ц, Ч, Щ, Ъ, Ы, Ь для осей не применяются (в строке `AX_LET` сейчас есть «Ц» — при правке осей убрать). Марка оси — в кружке.
- Размеры на плане — три цепочки снаружи: привязки проёмов, между осями, габарит.
- Фасады (`sheetFacades`): виды строятся из одной модели — `facadeFaces()` собирает грани (стены по контуру с фронтонами, кровля с толщиной, проёмы, сваи), видимость — сортировкой по глубине; названия по крайним осям («Фасад 1–5», «Фасад А–Г»).
- Помещения на плане: номер в кружке, название, площадь в м² с одним знаком, подчёркнута. Экспликация: №, наименование, площадь, категория; итог и жилая площадь.
- Проёмы маркируются: `ОК-n` окна, `Д-n` двери (одинаковые размеры — одна марка). Ведомость проёмов — черновые размеры.
- Линии (классы `SVG_CSS`): `m` — основная 0,5; `t` — тонкая; `ax` — штрихпунктир осей; `hd` — штриховая. Текст — наклонный узкий шрифт. В DXF классы переходят в слои (`CLS_LAYER`), текст — в кодировке Windows-1251.

## 3. Нагрузки (СП 20.13330)

- Коэффициенты надёжности γf: дерево 1,1; утеплитель и отделка 1,2; полезная при нормативной до 2 кПа 1,3; снег 1,4; ветер 1,4. Сочетание снега и ветра — коэффициент 0,9.
- Снег: S = Sg·μ; μ = 1 при α ≤ 30°, (60 − α)/30 при 30–60°, 0 при α ≥ 60°. Районы Sg, кПа: I 0,5; II 1,0; III 1,5; IV 2,0; V 2,5; VI 3,0; VII 3,5; VIII 4,0.
- Ветер: w = w0·k·c; k для z ≤ 5 м: A 0,75, B 0,5, C 0,4; c — наветренная +0,8, заветренная −0,5, отсос на скате −0,6. Районы w0, кПа: Ia 0,17; I 0,23; II 0,30; III 0,38; IV 0,48; V 0,60; VI 0,73; VII 0,85.
- Полезные нормативные: пол жилого дома 1,5 кПа, холодный чердак 0,7 кПа, мансарда 1,5 кПа.
- Климат по городу (Open-Meteo, ERA5): средние значения — только оценка; для проекта — повторяемость 1 раз в 50 лет (Гумбель, x₅₀ = x̄ + 2,59σ). Промерзание по СП 22.13330: d = d₀·√Mt.

## 4. Дерево и узлы (СП 64.13330)

- Сосна 2 сорта: Rи = Rс = 13 МПа, Rр = 7 МПа, E = 10 000 МПа. Прогиб: пол L/250, кровля L/200.
- Стойки: N/(φ·A·Rс) + M/(W·Rи) ≤ 1; φ = 1 − 0,8(λ/100)² при λ ≤ 70, иначе 3000/λ²; λ ≤ 120.
- Жёсткость стен: укосины 45–60° обоих направлений от нижней до верхней обвязки; если по месту не помещаются — эта стена автоматически получает плитную обшивку (OSB-3, фанера, ЦСП). Обшивка работает участками шириной не менее h/4.
- Ростверк: брус или пакет 2–4 досок «ёлочкой» — стыки досок вразбежку и только над сваями.
- Сечения берутся только из базы `P.db` (доска сухая строганая / обрезная / брус) выбранного типа; при смене типа — `mapToDb()` и автоподбор `autoFix()` в рамках технологии (`TECH`).

## 4а. Стропильная система и узлы

- Конёк (`P.ridgeJoint`): `butt` — в стык с подрезкой (торцы запилены по уклону, накладки 25×100 на гвоздях; на прогоне каждое стропило на половине ширины); `lap` — внахлёст (стропила пары сдвинуты на толщину, заход за конёк 1,5h, болт М12 — нагель по СП 64: T = min(0,8·a·d; 1,8d² + 0,02a² ≤ 2,5d²); на прогоне подрезка не глубже h/4). Проверка `node_ridge` в обеих системах.

- Две системы (`P.rafterSys`): **висячая** (`hang`) — балки перекрытия работают затяжками, на коньке накладки, проверки `node_tie` (распор H = q·s·B/(4·tg α), гвозди по СП 64) и `node_ridge` (односторонний снег V = S·s·B/8); **наслонная** (`purlin`) — коньковый прогон КП на стойках СТК, стойки на лежне ЛЖ; проверки `purlin`, `post` (λ ≤ 120), `notch` (врубка ≤ 1/3 h по СП 64.13330, рекомендуется ≤ 1/4 h), `bearing` (смятие поперёк волокон Rсм.90 = 3 МПа), `ridge_fix` (отрыв ветром).
- Стойки прогона опираются на лежень; без несущей перегородки под коньком нагрузка идёт на балки перекрытия сосредоточенной силой (учтено в `attic`).
- Мансарда — своя схема (стенки, ригели), прогон не применяется.
- Крылья: ендовная балка ЕН — сдвоенное стропило, проверка `valleyN` (упрощённо, однопролётная, нагрузка с нарожников двух скатов).

## 5. Сваи (СП 24.13330, СП 22.13330)

## 6. Проверка после каждой правки

Основной способ — скилл **karkas-check** (`node build.mjs && node tools/check.cjs`). Пункты ниже — что смотреть глазами.

Python-Playwright в облачной среде не установлен — использовать Node: `require('playwright')`, `chromium.launch()` без параметров (см. также скилл webapp-testing).

1. Открыть `file:///…/index.html`, собрать ошибки `pageerror` и `console.error` (ошибка загрузки шрифтов/CDN без интернета допустима, ошибки JS — нет).
2. Проверить модель через глобальные `M`, `C`, `S`, `SHEETS`, `tep(M)`: площади помещений сверить с ручным расчётом.
3. Отрисовать затронутые листы: `SHEETS.find(s=>s.code==='АР-1').svg` → отдельная страница → скриншот; смотреть наложения текста, выход за рамку, перекрытие штампа (штамп занимает x 230–415, y 237–292).
4. Проверить шаблоны (`TEMPLATES`, хотя бы t97 и t1210) и что старый JSON проекта открывается.
5. Коммит в `main` с понятным описанием на русском; README/CLAUDE.md — если поменялись правила.
